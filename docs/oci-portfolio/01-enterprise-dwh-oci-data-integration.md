# Project 1 — Enterprise DWH on OCI (Autonomous DB + OCI Data Integration)

Build a production-style **star-schema data warehouse** on **Autonomous Data Warehouse (ADW)** with ETL orchestrated by **OCI Data Integration** — Oracle's cloud-native successor to classic ODI workflows.

## Skills demonstrated

- Dimensional modeling (star schema, SCD Type 2)
- **OCI Data Integration** pipelines (mapping, parameters, scheduling)
- **Autonomous Database** administration (schemas, privileges, performance)
- Data quality reconciliation and audit logging
- Object Storage integration

## OCI services used

| Service | Role |
|---------|------|
| PORTFOLIO_ATP (Autonomous DB) | Simulated ERP/CRM source |
| PORTFOLIO_ADW (Autonomous DB) | Enterprise DWH |
| OCI Data Integration | Cloud ETL workspace + pipelines |
| Object Storage | Landing CSV files |
| Vault | Credentials for connections |

## Prerequisites

- [00-shared-oci-setup.md](./00-shared-oci-setup.md) completed
- ~2 hours for initial OCI Data Integration workspace provisioning

## Architecture

```text
Object Storage (CSV) ──┐
                       ├──► OCI Data Integration ──► ADW (DWH schema)
PORTFOLIO_ATP (OLTP) ──┘         │
                                 └──► ETL_AUDIT tables
```

## Phase 1 — Source data on ATP (Day 1)

### Step 1.1 — Create OLTP tables

Connect to **PORTFOLIO_ATP** as `OLTP_SHOP` (SQL Developer Web).

```sql
CREATE TABLE customers (
    customer_id      NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    full_name        VARCHAR2(200) NOT NULL,
    email            VARCHAR2(200),
    city             VARCHAR2(100),
    country          VARCHAR2(2) DEFAULT 'BR',
    status           VARCHAR2(20) DEFAULT 'ACTIVE',
    created_at       TIMESTAMP DEFAULT SYSTIMESTAMP,
    updated_at       TIMESTAMP DEFAULT SYSTIMESTAMP
);

CREATE TABLE products (
    product_id       VARCHAR2(32) PRIMARY KEY,
    product_name     VARCHAR2(200) NOT NULL,
    category         VARCHAR2(100),
    unit_price       NUMBER(12,2) NOT NULL,
    updated_at       TIMESTAMP DEFAULT SYSTIMESTAMP
);

CREATE TABLE orders (
    order_id         VARCHAR2(32) PRIMARY KEY,
    customer_id      NUMBER NOT NULL REFERENCES customers(customer_id),
    order_date       DATE NOT NULL,
    status           VARCHAR2(20) DEFAULT 'COMPLETED',
    last_updated_at  TIMESTAMP DEFAULT SYSTIMESTAMP
);

CREATE TABLE order_items (
    order_item_id    NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    order_id         VARCHAR2(32) NOT NULL REFERENCES orders(order_id),
    product_id       VARCHAR2(32) NOT NULL REFERENCES products(product_id),
    quantity         NUMBER NOT NULL,
    unit_price       NUMBER(12,2) NOT NULL,
    last_updated_at  TIMESTAMP DEFAULT SYSTIMESTAMP
);

CREATE INDEX ix_orders_customer ON orders(customer_id);
CREATE INDEX ix_orders_date ON orders(order_date);
CREATE INDEX ix_items_order ON order_items(order_id);
```

## Phase 2 — DWH model on ADW (Day 1–2)

Connect to **PORTFOLIO_ADW** as `DWH`.

### Step 2.1 — Create dimensions and facts

```sql
CREATE TABLE d_date (
    date_key        NUMBER PRIMARY KEY,    -- YYYYMMDD
    full_date       DATE NOT NULL,
    year_num        NUMBER(4),
    month_num       NUMBER(2),
    day_num         NUMBER(2),
    quarter_num     NUMBER(1),
    month_name      VARCHAR2(20)
);

CREATE TABLE d_customer (
    customer_key    NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    customer_id     NUMBER NOT NULL,
    full_name       VARCHAR2(200),
    email           VARCHAR2(200),
    city            VARCHAR2(100),
    country         VARCHAR2(2),
    status          VARCHAR2(20),
    effective_from  DATE NOT NULL,
    effective_to    DATE DEFAULT DATE '9999-12-31',
    is_current      CHAR(1) DEFAULT 'Y'
);

CREATE TABLE d_product (
    product_key     NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    product_id      VARCHAR2(32) NOT NULL,
    product_name    VARCHAR2(200),
    category        VARCHAR2(100),
    unit_price      NUMBER(12,2)
);

CREATE TABLE f_sales (
    sales_key       NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    date_key        NUMBER NOT NULL,
    customer_key    NUMBER NOT NULL,
    product_key     NUMBER NOT NULL,
    order_id        VARCHAR2(32),
    quantity        NUMBER,
    unit_price      NUMBER(12,2),
    revenue         NUMBER(14,2),
    batch_id        VARCHAR2(50),
    loaded_at       TIMESTAMP DEFAULT SYSTIMESTAMP
);

CREATE INDEX ix_f_sales_date ON f_sales(date_key);
CREATE INDEX ix_f_sales_customer ON f_sales(customer_key);
```

### Step 2.2 — Populate date dimension (10 years)

```sql
INSERT INTO d_date
SELECT TO_NUMBER(TO_CHAR(d, 'YYYYMMDD')),
       d,
       EXTRACT(YEAR FROM d),
       EXTRACT(MONTH FROM d),
       EXTRACT(DAY FROM d),
       TO_NUMBER(TO_CHAR(d, 'Q')),
       TRIM(TO_CHAR(d, 'Month'))
FROM (
  SELECT DATE '2020-01-01' + LEVEL - 1 AS d
  FROM dual
  CONNECT BY LEVEL <= 3653
);
COMMIT;
```

### Step 2.3 — ETL audit tables (as ADMIN or ETL_AUDIT user)

On ADW:

```sql
CREATE TABLE etl_audit.etl_run_log (
    run_id          VARCHAR2(50) PRIMARY KEY,
    pipeline_name   VARCHAR2(200),
    started_at      TIMESTAMP,
    ended_at        TIMESTAMP,
    status          VARCHAR2(20),
    rows_inserted   NUMBER,
    rows_updated    NUMBER,
    error_message   VARCHAR2(4000)
);

CREATE TABLE etl_audit.etl_reconciliation (
    run_id          VARCHAR2(50),
    check_name      VARCHAR2(100),
    source_count    NUMBER,
    target_count    NUMBER,
    passed          CHAR(1),
    checked_at      TIMESTAMP DEFAULT SYSTIMESTAMP
);
```

Grant access:

```sql
GRANT SELECT, INSERT, UPDATE ON etl_audit.etl_run_log TO dwh;
GRANT SELECT, INSERT ON etl_audit.etl_reconciliation TO dwh;
```

## Phase 3 — OCI Data Integration workspace (Day 2)

### Step 3.1 — Create workspace

1. Console → **Analytics & AI** → **Data Integration** → **Workspaces**.
2. **Create workspace**.
3. Name: `portfolio-etl-ws`
4. Compartment: `portfolio-data`
5. VCN: `portfolio-vcn` → **private subnet**
6. Click **Create** (takes 15–30 minutes).

### Step 3.2 — Create connections

Open workspace → **Connections** → **Create connection**.

**Connection 1: ATP_SOURCE**

| Field | Value |
|-------|-------|
| Type | Oracle Autonomous Data Warehouse *(works for ATP too)* |
| Name | `ATP_SOURCE` |
| URL | From ATP wallet: `portfoli_atp_high` JDBC URL |
| Username | `OLTP_SHOP` |
| Password | Vault secret or manual |
| Wallet | Upload `Wallet_PORTFOLIOATP.zip` |

**Connection 2: ADW_DWH**

| Field | Value |
|-------|-------|
| Name | `ADW_DWH` |
| URL | ADW high service |
| Username | `DWH` |
| Wallet | `Wallet_PORTFOLIOADW.zip` |

**Connection 3: OCI_OBJECT_STORAGE**

| Field | Value |
|-------|-------|
| Type | Oracle Object Storage |
| Name | `OBJ_STORE` |
| Tenancy OCID | your tenancy |
| Region | your home region |
| Namespace | from `oci os ns get` |

Test each connection → status must be **Successful**.

## Phase 4 — Build pipelines (Day 3–5)

### Step 4.1 — Pipeline: `PL_DIM_PRODUCT`

1. **Create data flow** → name `DF_DIM_PRODUCT`.
2. Source: `ATP_SOURCE.OLTP_SHOP.PRODUCTS`
3. Target: `ADW_DWH.DWH.D_PRODUCT`
4. Mapping logic:
   - Map columns 1:1
   - Filter: none (full load for lab)
5. Add **Target** operator with **Insert** strategy.
6. Save and **Publish**.

Create **Pipeline** `PL_DIM_PRODUCT`:

1. Add task → Run data flow `DF_DIM_PRODUCT`.
2. Parameter: `BATCH_ID` (string, default `manual`).

### Step 4.2 — Pipeline: `PL_DIM_CUSTOMER_SCD2`

Data flow logic (use **Derived Column** / SQL transform):

- Compare source `CUSTOMERS` to current `D_CUSTOMER` where `IS_CURRENT = 'Y'`.
- If attribute changed: expire old row (`EFFECTIVE_TO = yesterday`, `IS_CURRENT = 'N'`), insert new row.
- If new customer: insert with `EFFECTIVE_FROM = today`.

Simplified lab approach — two targets in sequence:

1. **Update** expired rows (SQL operator or staging table).
2. **Insert** new/changed versions.

### Step 4.3 — Pipeline: `PL_FACT_SALES`

Source SQL (on ATP):

```sql
SELECT o.order_id,
       TO_NUMBER(TO_CHAR(o.order_date, 'YYYYMMDD')) AS date_key,
       c.customer_id,
       oi.product_id,
       oi.quantity,
       oi.unit_price,
       oi.quantity * oi.unit_price AS revenue
FROM orders o
JOIN order_items oi ON oi.order_id = o.order_id
JOIN customers c ON c.customer_id = o.customer_id
WHERE o.last_updated_at > :LAST_WATERMARK
```

Target: `F_SALES` with lookup to `D_CUSTOMER` (current) and `D_PRODUCT` on natural keys.

Parameter: `LAST_WATERMARK` (timestamp, default `1900-01-01` for first run).

### Step 4.4 — Pipeline: `PL_LOAD_PRODUCTS_CSV`

1. Source: Object Storage `bronze/products/products_ext.csv` (format: CSV, header row).
2. Stage to `STG.PRODUCTS_EXT` on ADW (optional external table).
3. Merge into `D_PRODUCT` / source `PRODUCTS` on ATP via cross-database link or land only on ADW for lab.

### Step 4.5 — Master pipeline: `PL_DWH_NIGHTLY`

Orchestration order:

```text
1. Log start → etl_audit.etl_run_log
2. PL_DIM_PRODUCT
3. PL_DIM_CUSTOMER_SCD2
4. PL_FACT_SALES
5. Reconciliation SQL task
6. Log end
```

Reconciliation SQL (run on ADW):

```sql
INSERT INTO etl_audit.etl_reconciliation (run_id, check_name, source_count, target_count, passed)
SELECT :BATCH_ID, 'ORDER_ITEMS_VS_F_SALES',
       (SELECT COUNT(*) FROM order_items@atp_link),  -- or hardcoded source count in lab
       (SELECT COUNT(*) FROM dwh.f_sales),
       CASE WHEN ... THEN 'Y' ELSE 'N' END
FROM dual;
```

> **Lab shortcut:** If database link to ATP is not configured, run reconciliation in a **Python post-step** using two JDBC connections and write results to `etl_reconciliation`.

## Phase 5 — Schedule and test (Day 5–6)

### Step 5.1 — Schedule

1. Pipeline `PL_DWH_NIGHTLY` → **Schedule**.
2. Cron: `0 6 * * *` (06:00 UTC daily) or manual trigger for portfolio demo.

### Step 5.2 — Test cases

| Test | Action | Expected |
|------|--------|----------|
| Full load | Reset watermark, run pipeline | All dims + facts populated |
| Incremental | Insert new order on ATP, re-run | New fact rows only |
| SCD2 | Update customer city on ATP | New `D_CUSTOMER` row, old expired |
| Failure | Break connection password, run | `etl_run_log.status = FAILED` |
| Reconciliation | Compare counts | `passed = Y` |

### Step 5.3 — Sample analytics queries

```sql
-- Revenue by category
SELECT p.category, SUM(f.revenue) AS revenue
FROM f_sales f
JOIN d_product p ON p.product_key = f.product_key
GROUP BY p.category;

-- Monthly trend
SELECT d.year_num, d.month_num, SUM(f.revenue)
FROM f_sales f
JOIN d_date d ON d.date_key = f.date_key
GROUP BY d.year_num, d.month_num
ORDER BY 1, 2;
```

## Troubleshooting

| Issue | Fix |
|-------|-----|
| Connection test fails | Re-upload wallet; verify service name `_high`; check ACL allows Data Integration subnet |
| Pipeline slow | Use ADW **auto-scaling** temporarily; reduce full-scan sources |
| SCD2 duplicates | Add unique constraint on `(customer_id, effective_from)` |
| Cross-DB reconciliation | Use DB link or external Python validator |
